## Lessons the real City taught (worth knowing before touching this code)

- The City's SQL endpoint **refuses** `NULLIF`, `substr` and `COUNT(*) FILTER` (HTTP 403). Dates are ISO text, so queries compare them **as text**. Accepted: `COUNT`, `MIN/MAX`, `left()`, `IN`, `LIKE`, `||`, `unnest(string_to_array(col, ';'))`, `GROUP BY alias`. Prove any new shape with `npx tsx scripts/city-sql-smoke.ts` (free, read-only).
- Many City datasets come as a **Current** and a **Historical** file updated the same day. Counts must read **Current** (it once read Historical → "this year" crime would have been 0).
- Crime offenses are **semicolon lists** (`13B;13C`): counts match a code anywhere in the list (robbery 4,162 since 2024 vs 3,115 before the fix).
- The City re-saves static map layers daily: **every City family is dated by when the City created it**, never by its daily "modified" date (otherwise maps flood "Updated this season").
- Cards must say what period the data covers; a period entirely outside → "outside the data's range", never 0.

## Rulings I made (Tarik: rework anything you disagree with)

Pre-flight / tasks:
- First profile never re-dates a family; only a later column change does (spec: no flooding).
- Unknown election month keys stay as the plan wrote them (all 4 real election dates valid).
- `profileSql(rid, plan)` has no `today` argument (plan header listed one its code never used).
- An empty or blank offense word matches **no** codes (never "all offenses").
- City SQL treats dates as ISO **text**: no casts, no `NULLIF` (live probe).
- Dates: impossible calendar dates rejected; default start = end − 365 days; start after end → "bad dates", never a 0.
- Month/year groups keep the **newest** 24, shown oldest→newest; the rest labeled "Earlier".
- CITY is accepted by the tag component only; the stored-provenance type stays as it was.
- The private-names note shows whenever the flag is set, independent of live rows.
- Counts prefer the "(Current)" file.
- City families without a CKAN group get a topic from department, then title (53 X → 6); dev keeps its old X codes (codes are permanent); prod starts clean.
- Card glossary cap raised to 200 with trimming, instead of 80 (the property file has 92 columns).
- Prose check allows districts, wards, ZIPs, street addresses, calendar dates, and durations only when the same phrase is in the data; district/ward numbers can't swallow a following count.
- Every City family is dated by City creation date.
- The home e2e checks the rundown's shape, not which dataset is newest.

Final review:
- Multi-offense counts via `LIKE` on `;`-joined codes; profiles and groups via `unnest`; codes in LIKE limited to `/^[0-9A-Z]{2,4}$/`; overlapping groups have no "Other" and say so.
- Cards always show coverage; outside → "outside the data's range"; partial → clamped and said; multi-file packages count the newest file and name it.
- Person-name columns (licensee, applicant, agent, contact, operator, dispatcher, call taker, changed by, officer, person id, owner …) are never countable and flag the dataset as naming people — **editorial call made conservatively** under "Ask counts; names stay on the sheet".
- Cards say which date column they count by; no expiry/edit/last-updated date as the count date.
- Shrink guard checks DYCU and City separately; a City-only shrink keeps last week's City families.
- Stale profiles deleted (no live file, unreadable columns, retired family).
- ID-like columns kept off the menu; election families not countable (a count there is wards); a DYCU code says "not City data".
- **Parked:** filtering by weapon (`Weapon_Used_All` values like "FIREARM") — grouping by weapon works; widening the safety rule needs its own careful test.
- File name stored only for multi-file packages; a feed whose newest record is under 31 days old counts as running to today; `coverage` is now a string.
